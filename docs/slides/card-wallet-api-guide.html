Card Wallet API · 02 · всё запускается одной командой: docker compose up -d

Клиент общается только с Wallet API по REST. Перед каждым платежом Wallet API спрашивает антифрод по gRPC — одобрить или отклонить. Данные хранятся в PostgreSQL.

Общие правила

Адрес, токен и формат ошибок

Базовый адрес: http://localhost:8000/api/v1 · Swagger: /docs

Авторизация

Authorization: Bearer <token>

Нужна везде, кроме health, register и login. Токен живёт 60 минут. Нет токена или он просрочен → 401.

Любая ошибка

{ "error": {
"code": "CARD_BLOCKED",
"message": "Card is blocked" } }

Клиент опирается на code, а не на текст сообщения.

Card Wallet API · 03

JWT-токен сам содержит id пользователя и срок действия, сервер не хранит сессию. Единый формат ошибок позволяет фронтенду и автотестам разбирать все ошибки одним кодом. Для 422 добавляется список details с полем и проблемой.

Общие правила

Коды ответов

КодКогда
200Успешное чтение или действие без создания объекта
201Создан объект: пользователь, счёт, карта, операция
401Нет токена, он неверный — или неверный логин/пароль
404Объект не найден или принадлежит другому клиенту
409Конфликт: дубликат, лимит карт, повтор ключа идемпотентности
422Ошибка в данных запроса
503Антифрод-сервис недоступен — платёж не проведён

Почему 404, а не 403? 403 выдал бы, что объект с таким id существует. С 404 «чужое» не отличить от «несуществующего» — защита от перебора чужих id (IDOR).

Card Wallet API · 04

Отдельно стоит запомнить: отклонённый платёж — это тоже 201, потому что операция создана со статусом DECLINED. Об этом подробнее в разделе платежей.

Общие правила

Деньги, время и идентификаторы

"100.00"

Деньги — строкой

В ответах всегда строка с двумя знаками. В запросе можно строку или число, но не больше 2 знаков после точки.

Почему: float теряет точность — 0.1 + 0.2 = 0.30000000000000004.

…Z

Время — в UTC

Формат ISO 8601 с буквой Z на конце: 2026-11-08T13:06:26Z.

Почему: одна шкала времени для всех клиентов; дневной лимит тоже считается по UTC.

UUID

ID и текст

Все id — UUID; не UUID в адресе → 422.

Нулевой символ \u0000 в любом тексте → 422: PostgreSQL не умеет его хранить.

Card Wallet API · 05

Правило про нулевой символ появилось после того, как контрактные тесты нашли ошибку 500 на таком вводе. Хороший пример для собеседования.

Card Wallet API · 08

Ограничение «один счёт на валюту» закреплено уникальным ключом user_id + currency в базе, поэтому оно соблюдается даже при одновременных запросах.

Счета · BR-ACC-03

POST

/accounts/{id}/top-up

Одно поле — amount, обязательно. Валюту передавать не нужно: пополнение всегда в валюте счёта. Ответ 201: операция TOP_UP и новый баланс.

Проходит

"0.01" — минимум
"10000.00" — максимум
10.1 → "10.10"

Отказ 422

"0", "-1", "10000.01"
"10.555" — 3 знака
"abc", true, null

Почему лимит 10 000 за операцию: типичное правило для пополнений — защищает от ошибок ввода и подозрительно крупных зачислений.

Card Wallet API · 09

Это классический набор граничных значений для тест-дизайна: минимум, максимум, чуть больше максимума, ноль, отрицательное, лишний знак после точки, неверный тип.

Карты · BR-CARD

POST

/accounts/{id}/cards

daily_limit — необязательно, по умолчанию 1000.00, от 1.00 до 10000.00. Тело можно отправить пустым: {}.

201 →
{ "pan": "4000001234567890",
"cvv": "123",
"expiry": "11/29",
"status": "ACTIVE", … }

Номер и CVV — один раз

Дальше видно только **** **** **** 7890. В базе — последние 4 цифры, ключевой хеш номера и bcrypt-хеш CVV.

Так работают виртуальные карты в банках: восстановить данные из базы нельзя.

Номер начинается с вымышленного 400000 и проходит проверку Луна · срок — конец месяца через 3 года · 409 CARD_LIMIT_REACHED — уже 3 активные карты на счёте

Card Wallet API · 10

Максимальный дневной лимит 10 000 равен максимальной сумме платежа. Изначально был 5 000, и тогда правило антифрода «сумма больше 5 000» никогда бы не сработало — это противоречие нашли ещё на этапе анализа требований.

Card Wallet API · 12

Ошибки этого эндпоинта: 404 — чужая или несуществующая карта; 409 — ключ уже использован с другими данными; 422 — неверные поля или нет заголовка; 503 — антифрод недоступен.

Card Wallet API · 13

Хороший тест на порядок проверок: карта одновременно заблокирована и истекла — ответ должен быть CARD_BLOCKED, потому что эта проверка идёт первой.

Платежи · BR-PAY-03, BR-PAY-04, BR-CARD-06

Комиссия, лимит и неверный CVV

1%

Комиссия

Минимум 0.50, округление «половина вверх». Только при одобрении, отдельной операцией COMMISSION.

10.00 → 0.50
100.00 → 1.00
150.50 → 1.51

00:00

Дневной лимит

По карте, за календарный день по UTC. Считаются только одобренные платежи, без комиссии.

Ровно до лимита — можно.

3

Неверных CVV

Три подряд — карта блокируется: TOO_MANY_FAILED_ATTEMPTS.

Успешный платёж обнуляет счётчик; другие отказы его не меняют.

Card Wallet API · 14

Пример на баланс: на счёте 100.00, платёж 99.50 требует 100.50 с комиссией и будет отклонён, а платёж 99.00 требует 99.99 и пройдёт. Это хороший граничный тест.

Платежи · BR-PAY-07, BR-PAY-09

Связь оборвалась — деньги не спишутся дважды

Клиент не получил ответ и повторил платёж. Сервер узнаёт повтор по заголовку Idempotency-Key и возвращает прежний результат. Так работают Stripe и другие платёжные API.

Тот же ключ + те же данные

Тот же ответ, повторного списания нет

Тот же ключ + другие данные

409 IDEMPOTENCY_KEY_REUSED

Два платежа одновременно

Счёт блокируется в базе — баланс не уйдёт в минус

Card Wallet API · 15 · ключи у каждого клиента свои · CVV в сравнение не входит

Пример параллельности: баланс 100.00, два одновременных платежа по 60.00 — один одобрен, второй отклонён с INSUFFICIENT_FUNDS. Если антифрод недоступен (503), ничего не сохраняется и тот же ключ можно использовать снова.

Выписка · BR-STM

GET

/accounts/{id}/transactions

Все параметры необязательные. Сначала новые операции; total — сколько всего подходит под фильтры.

ПараметрПо умолчаниюПравила
date_from—YYYY-MM-DD, включительно
date_to—YYYY-MM-DD, включительно, не раньше date_from
status—APPROVED или DECLINED

Почему страницы и максимум 100: у реального клиента тысячи операций — отдавать всё разом медленно, а один запрос не должен «положить» сервер.

Card Wallet API · 16

Пример: ?status=DECLINED&limit=10 — только отказы, по 10 на страницу. Баланс счёта всегда равен сумме одобренных пополнений минус платежи и комиссии — это проверяет SQL-тест.

Тестовые магазины

TEST_TIMEOUT — ответ через 5 с, Wallet ждёт 2 с → 503

TEST_ERROR — ошибка gRPC → 503

Postman: New → gRPC → localhost:50051 → методы подтянутся через server reflection

Почему gRPC, а не REST: это внутренний вызов между сервисами — бинарный формат быстрее, а контракт строго описан в .proto-файле, из которого генерируется код для обеих сторон.

Card Wallet API · 17 · контракт: proto/fraudpb/fraud.proto

Вызывать антифрод напрямую нужно только для тестов — Wallet API делает это сам перед каждым платежом. Тестовые магазины работают как тестовые номера карт в песочницах платёжных систем.
