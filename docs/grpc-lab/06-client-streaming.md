# Урок 6. Поток от клиента: CheckBatch

## Зачем

Ночью банк перепроверяет пачку вчерашних платежей. Отправлять 1000 отдельных вызовов долго,
собрать гигантское сообщение — тяжело. **Поток от клиента** (client streaming): клиент шлёт
платежи по одному в одном вызове, а сервер в конце отвечает **один раз** итогом.

`CheckBatch` (BR-FRD-08):
- ответ: `total`, `approved`, `declined` и список отклонённых `transaction_id` по порядку;
- пустая пачка → `INVALID_ARGUMENT`;
- больше **1000** платежей → `RESOURCE_EXHAUSTED`;
- хотя бы один платёж с неверной суммой → `INVALID_ARGUMENT` с номером (`index 1`, счёт с нуля),
  и **вся пачка отклоняется**: ни одно решение не сохраняется («всё или ничего»).

## Попробуй в Postman

1. `CheckBatch`, metadata `x-api-key: dev-wallet-key`, **Invoke** — вызов открылся и ждёт сообщений.
2. Отправь (**Send**) три сообщения: обычный платёж, `"amount": "6000.00"`, категория
   `GAMBLING`. Пока ответа нет.
3. Нажми **End streaming** — придёт один ответ: `total 3, approved 1, declined 2`.
4. Повтори, но второй платёж с `"amount": "abc"` → `INVALID_ARGUMENT`, в тексте `index 1`.
   Проверь `GetDecision` по `transaction_id` первого платежа → `NOT_FOUND`: пачка не сохранилась.
5. Попробуй с ключом мониторинга → `PERMISSION_DENIED`.

## Посмотри в коде

```python
batch = [payment(), payment(), payment(amount="6000.00")]
summary = stub.CheckBatch(iter(batch), metadata=WALLET, timeout=5)
```

Поток от клиента в Python — это **итератор**: список через `iter(...)` или генератор
`(payment() for _ in range(1001))`. Генератор не держит все 1001 платёж в памяти сразу.

Сервер: `server.py` → `CheckBatch`: сначала читает всё, проверяет каждую сумму, только потом
принимает решения.

## Вопросы с собеседования

1. Когда нужен client streaming?
2. Какие граничные значения у лимита пачки?
3. Что значит «всё или ничего» и как это проверить?

### Ответы

1. Загрузка большого объёма данных частями с одним итогом: пакетная проверка, загрузка файла.
2. 0 (пусто — ошибка), 1, 1000 (можно), 1001 (`RESOURCE_EXHAUSTED`).
3. Если в пачке есть ошибка, ничего из неё не применяется. Проверка: после ошибки найти первый
   (верный) элемент через `GetDecision` — должен быть `NOT_FOUND`.
