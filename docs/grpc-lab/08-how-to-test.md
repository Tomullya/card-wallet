# Урок 8. Как тестировать gRPC + охота на баги

## Зачем

Ты прошла все типы вызовов. Теперь главное для собеседования: **как ты тестируешь gRPC-сервис**
— стратегия, а не отдельные вызовы.

## Стратегия по слоям

| Слой | Что проверять | Где у нас |
|---|---|---|
| Контракт | proto компилируется; номера полей не меняются; reflection показывает методы | `tests/grpc/test_fraud_service.py::test_reflection_lists_service` |
| Логика | правила решений, границы (5000.00 / 5000.01) | `tests/unit/test_fraud_rules.py`, `test_fraud_service.py` |
| Metadata | ключи и роли, request id в trailers | `tests/grpc/test_metadata.py` |
| Статус-коды | каждый код получается там, где должен | `tests/grpc/test_status_codes.py` (карта) |
| Потоки | порядок, фильтры, завершение, лимиты, отмена | `test_server_streaming.py`, `test_client_streaming.py`, `test_bidi_streaming.py` |
| Время | дедлайны, медленная зависимость | `tests/grpc/test_deadlines.py` |
| Интеграция | кошелёк ↔ антифрод: 503 при сбое, событие после оплаты | `tests/integration/` |

**Правила хорошего gRPC-теста:**
1. У каждого вызова есть дедлайн.
2. Ошибку проверяй по коду, а не только по тексту.
3. Для потоков проверяй и сообщения, и **итоговый код** потока.
4. Состояние после ошибки: ничего не сохранилось (`CheckBatch`), деньги не списаны (кошелёк).
5. Тест «ловит» баг, только если падает на `assert`. Если он падает на ошибке вызова
   (сервис не запущен, опечатка), это не поимка — проверка `--buggy` покажет ⚠️.

## Охота на баги

На порту **50052** работает копия антифрода с тремя спрятанными багами (BUGGY_MODE).
Подсказки — по одной на баг:
1. Сравни, какой код приходит на **неизвестный** ключ на 50051 и на 50052.
2. Сравни, как **заканчивается** `ScorePayments` после **End streaming**.
3. Сравни **trailers** успешного `CheckPayment`.

Шаги:
1. Найди каждый баг руками в Postman (адрес `localhost:50052`).
2. Напиши баг-репорт в своём стиле (шаблон — любой из `docs/qa/bug-reports/`).
3. Допиши тесты в `grpc-lab/exercises/test_lab_09_bug_hunt.py` и проверь:
   ```bash
   .venv/bin/python scripts/grpc_lab_check.py 9          # на нормальном — всё зелёное
   .venv/bin/python scripts/grpc_lab_check.py 9 --buggy  # на сломанном — все три 🐞 «баг пойман»
   ```
4. Сравни со «взрослыми» репортами: BUG-17, BUG-18, BUG-19 в `docs/qa/bug-reports/`.
