# Plan 3 — QA Package Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the tested backend into a complete QA portfolio: automatic traceability matrix, BUGGY_MODE with reproducible planted defects, written QA documentation (test plan, test cases, checklists, bug reports), a Postman collection run by Newman, and a CI pipeline with an Allure report.

**Architecture:** Everything builds on Plan 1 (branch `feature/backend`); work happens on `feature/qa`. Tooling is small Python scripts in `scripts/` with unit-tested pure functions in `tests/unit/`. A second wallet container (`wallet-buggy`, port 8001, compose profile `buggy`) runs the same image with `BUGGY_MODE=true` against the same database. CI repeats exactly what `scripts/ci_local.sh` runs locally.

**Tech Stack:** Python 3.13, pytest, allure-pytest, Newman 6 (npm), Allure CLI (npm `allure-commandline`, needs Java), GitHub Actions, Docker Compose.

**Spec:** `docs/design/2026-11-08-card-wallet-design.md` §9 (Testing), §10 (BUGGY_MODE), §11 (CI); `docs/requirements/*.md`.

## Global Constraints

- QA documents are in English (public portfolio); the owner's Russian guides stay as they are.
- Every test case, checklist item and bug report references requirement IDs exactly as written in `docs/requirements/` (`BR-PAY-03`, `NFR-04`).
- BUGGY_MODE is **off by default**; only the `wallet-buggy` service sets `BUGGY_MODE=true`.
- Planted defects exactly as design §10: BUG-01 min commission ignored (BR-PAY-03); BUG-02 payment reaching the daily limit exactly is declined (BR-PAY-04); BUG-03 CVV counter not reset after approval (BR-CARD-06); BUG-04 `GET /cards/{id}` returns another client's card (BR-CARD-03).
- Only fictional data. No secrets in the repository other than the documented local-dev values already in `docker-compose.yml`.
- GitHub is unreachable from this machine: CI is verified by running `scripts/ci_local.sh`, and the workflow YAML is validated by parsing; the first real run happens after the first push.

## Review Focus

1. A planted-bug check must not count a **connection error** as "bug caught" (a stopped `wallet-buggy` makes every test fail). → Task 2.
2. A requirement ID with a typo in a marker (`BR-PAY-3`) must fail the traceability check, not silently create a new row. → Task 1.
3. BUGGY_MODE must be off when the variable is unset. → Task 2.
4. The Newman run must be repeatable: running the collection twice in a row passes both times. → Task 4.
5. A QA document referencing a test that does not exist (renamed or typo) must fail the docs check. → Task 3.

### Task 1: Traceability matrix generator

- Modify: `tests/conftest.py` (write collected markers when `REQ_REPORT` is set)
- Generated: `docs/qa/traceability-matrix.md`

**Interfaces:**
- Produces:
  - `traceability.load_requirements(req_dir: Path) -> dict[str, str]` — ID → title, parsed from headings `## <ID> <title>` where ID matches `^(BR-[A-Z]+-\d{2}|NFR-\d{2})$`.
  - `traceability.render_matrix(requirements: dict[str, str], coverage: dict[str, list[str]]) -> str` — Markdown: one row per requirement in document order (`| ID | Requirement | Tests | Count |`), uncovered rows show `**NOT COVERED**`, a summary line `Covered: X / Y`.
  - `traceability.check(requirements, coverage) -> list[str]` — problems: unknown IDs used in markers (`Unknown requirement ID in tests: BR-PAY-3`) and uncovered requirements.
  - CLI: `python scripts/traceability.py` collects tests (`pytest --collect-only -q` with `REQ_REPORT=<tmp json>`), writes `docs/qa/traceability-matrix.md`, prints problems, exits 1 if any.
  - `tests/conftest.py`: `pytest_collection_finish(session)` — when `REQ_REPORT` env is set, dump `{req_id: [nodeid, …]}` from every item's `req` markers.
