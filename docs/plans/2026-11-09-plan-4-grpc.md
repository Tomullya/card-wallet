# gRPC Deep Dive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the Fraud Service to all four gRPC call types with metadata auth, request ids and full status-code coverage, plant three gRPC defects, and ship a Russian hands-on trainer with auto-checked exercises.

**Architecture:** New RPCs live in the existing `fraud.v1.FraudService`; shared state (decision store, event hub) is in-memory in the fraud process; auth and request ids are a server interceptor. The wallet only changes its client to send metadata. The trainer is docs (`docs/grpc-lab/`) plus pytest exercises (`grpc-lab/`) that run against the live stack.

**Tech Stack:** Python 3.13, grpcio / grpcio-tools / grpcio-health-checking / grpcio-reflection ≥ 1.67, protobuf ≥ 5.28, pytest, Docker Compose.

**Spec:** `docs/design/2026-11-09-grpc-deep-dive-design.md`

## Global Constraints

- Proto stays backward compatible: no renumbered or removed fields; new field `CheckPaymentResponse.transaction_id = 4`.
- API keys: env `FRAUD_API_KEY_WALLET` default `dev-wallet-key`, `FRAUD_API_KEY_MONITOR` default `dev-monitor-key`; wallet env `FRAUD_API_KEY` default `dev-wallet-key`.
- Monitor role may call only `WatchRiskEvents` and `GetDecision`. Health and reflection need no key.
- Limits: 8 concurrent watchers; 1000 events per watcher queue (overflow → drop + log); 1000 payments per `CheckBatch`; 10 000 stored decisions.
- `x-request-id` is always returned in **trailing** metadata, success and error alike.
- Every streaming test passes a client `timeout` ≤ 5 s.
- Fraud buggy container: `fraud-buggy`, host port `50052`, compose profile `buggy`, env `BUGGY_MODE=true`.
- Every new test carries `@pytest.mark.req(...)` with an existing requirement id (traceability gate).
- Lessons are Russian; code, docs in `docs/` (except the lab and `api-guide.ru.md`), and commit messages are English.
- Regenerate protobuf code only with `scripts/gen_proto.sh` (writes both `wallet-api/fraudpb` and `fraud-service/fraudpb`).

## Review Focus

1. A client that sends `x-request-id` must get the **same** value back, also in `RiskEvent.request_id` — pinned in Task 3 (`test_request_id_reaches_risk_event`).
2. A watcher that disconnects must free its slot, or the 9th-subscriber limit eventually locks out everyone — pinned in Task 3 (`test_cancelled_watchers_free_their_slots`).
3. Existing callers (wallet, old tests, Postman collection) must keep working after auth is switched on — pinned in Task 2 (old `tests/grpc` and `tests/integration` suites stay green with the default-key fixture; Newman runs in CI).
4. A batch with an invalid item must not leave half the items stored/published — pinned in Task 4 (`test_invalid_item_rejects_whole_batch`).
5. Uppercase metadata keys from tools (`X-Api-Key`) — gRPC lowercases keys on the wire; pinned in Task 2 (`test_header_name_case_is_ignored`).
