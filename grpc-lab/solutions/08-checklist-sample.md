# Пример ответа к уроку 8: чек-лист тестирования gRPC-метода

Метод: `ScorePayments` (поток в обе стороны).

**Контракт**
- [ ] Метод виден через reflection, типы сообщений совпадают с proto.
- [ ] Новые поля не ломают старых клиентов (номера полей не менялись).

**Позитивные**
- [ ] Один платёж → один ответ; несколько → столько же ответов, в том же порядке.
- [ ] `transaction_id` ответа совпадает с запросом.
- [ ] Ответ приходит сразу, не дожидаясь конца потока.
- [ ] Поток заканчивается `OK`, когда клиент закончил отправку.

**Негативные и граничные**
- [ ] Неверная сумма в середине потока → `INVALID_ARGUMENT` с номером элемента; прошлые ответы валидны.
- [ ] Пустой поток → `OK`, ноль ответов.
- [ ] Без ключа → `UNAUTHENTICATED`; ключ мониторинга → `PERMISSION_DENIED`.

**Время и обрыв**
- [ ] Короткий дедлайн на медленном магазине → `DEADLINE_EXCEEDED`.
- [ ] Клиент отменил поток → сервер прекращает работу (`CANCELLED`).
- [ ] У каждого автотеста есть дедлайн — иначе зависший поток повесит CI.

**Наблюдаемость**
- [ ] `x-request-id` возвращается в trailers и попадает в лог и в события риска.
